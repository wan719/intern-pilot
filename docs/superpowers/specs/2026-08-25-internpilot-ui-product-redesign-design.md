# InternPilot 产品级界面重塑设计

日期：2026-08-25

状态：已完成讨论，待用户复核文档

目标分支：`codex/ui-product-redesign`

## 1. 背景

InternPilot 已具备完整的求职业务闭环，前端采用 Vue 3、Vite、TypeScript、Element Plus、Vue Router、Pinia、Axios、ECharts、Sass 和 WebSocket。现有界面功能完整且风格统一，但信息组织仍以传统中后台菜单为中心，用户难以从界面直接理解“从简历准备到投递跟踪”的连续求职旅程，用户端与管理后台的视觉语言也缺少明确分工。

本次改造参考 Art Design Pro 的清晰层级和成熟质感，但不复制其商业版页面、专有资源或工程骨架。改造在现有前端工程中渐进进行，保留现有业务能力、接口和数据流。

## 2. 目标与非目标

### 2.1 目标

- 将用户端从“功能菜单集合”重塑为面向行动的求职产品。
- 用工作台和五阶段旅程串联简历、岗位、匹配分析、面试准备和投递追踪。
- 为用户端和管理后台建立职责明确的双布局。
- 建立可维护的设计变量、Element Plus 主题和公共组件体系。
- 为用户端提供精细移动适配，同时保证管理后台移动端基础可用。
- 保持接口、权限、路由、WebSocket、打印和已有业务功能兼容。
- 让每批迁移都可独立构建、验证、提交和回退。

### 2.2 非目标

- 不修改后端接口契约或数据库结构。
- 不重写认证、权限、API、Pinia store、Token 或 WebSocket 机制。
- 不引入 Tailwind、shadcn-vue 或新的 UI 框架。
- 不整体移植 Art Design Pro 模板。
- 不在本轮实现全局暗黑模式。
- 不进行与界面重塑无关的业务重构。
- 不改变产品名称 InternPilot。

## 3. 已确认的设计决策

| 决策项 | 结论 |
| --- | --- |
| 改造级别 | 产品级重塑，保留功能和接口，重做导航、工作台、页面布局与交互层级 |
| 实施路线 | 在原工程中渐进重塑 |
| 用户端导航 | 顶栏旅程式布局 |
| 管理后台导航 | 深色分组侧边栏 |

| 样式技术 | Sass + Element Plus + CSS 设计变量 |
| 移动端 | 用户端精细适配，管理后台基础可用 |

## 4. 信息架构

### 4.1 用户端

用户端采用“工作台 + 五阶段求职旅程”顶栏，现有路由路径保持不变，仅改变导航归属、页面标题和交互层级。

| 导航领域 | 路由与页面 | 主要目的 |
| --- | --- | --- |
| 工作台 | `/dashboard` | 展示今日行动、准备度、近期结果和快捷入口 |
| 简历中心 | `/resumes`、`/resumes/:resumeId/versions` | 上传、维护、设为默认和管理简历版本 |
| 岗位机会 | `/jobs`、`/job-recommendations`、`/job-recommendations/:batchId` | 锁定目标岗位并查看推荐机会 |
| 匹配分析 | `/analysis/match`、`/analysis/reports` | 创建 AI 匹配任务、跟踪进度和查看报告 |
| 面试准备 | `/interview-questions`、`/interview-questions/:id` | 生成和学习针对性面试题 |
| 投递追踪 | `/applications` | 跟踪投递状态、时间与后续行动 |

`/user/center` 放入右上角头像菜单。AI 任务中心和反馈入口保留为全局功能，但从多个悬浮按钮整合进顶栏操作区。`/analysis/reports/:id/print` 继续使用独立无导航打印布局。

桌面端使用顶栏。移动端使用紧凑顶部栏和底部核心导航；低频入口放入“更多”抽屉，避免底部导航拥挤。

### 4.2 管理后台

管理后台保留独立布局，并将侧边栏按任务分组：

- 后台概览：`/admin/dashboard`
- 用户与权限：`/admin/users`、`/admin/roles`、`/admin/permissions`
- AI 知识：`/admin/rag-knowledge`
- 运营管理：`/admin/operation-logs`、`/admin/feedback`

权限过滤继续使用现有 `auth.hasPermission`。后台顶部保留“返回用户工作台”。移动端将固定侧边栏切换为抽屉，不为管理表格制作与桌面端完全等价的手机操作体验。

## 5. 视觉系统

### 5.1 品牌与语义颜色

建议基础令牌如下，实施时允许为对比度做小幅调整，但不得改变整体方向：

- 导航炭黑：`#111827`
- 主强调松石绿：`#0F9F8F`
- 强调深色：`#0F766E`，用于浅色背景上的文字和需要更高对比度的状态
- 主文字：`#17202A`
- 次级文字：`#64748B`
- 页面背景：`#F6F8F8`
- 卡片背景：`#FFFFFF`
- 边框：`#E2E8E6`
- 信息：蓝色系
- 提醒：琥珀色系
- 危险：红色系
- 成功：与主色可区分的绿色系，并同时使用文字或图标表达状态

主色表示品牌与主要行动，不滥用于所有成功状态。禁止仅靠颜色传达状态。

### 5.2 排版、间距与形态

- 使用本地系统字体栈，不加载外部字体资源。
- 数据数字启用等宽数字特性，避免指标刷新时跳动。
- 采用 4/8 像素间距体系。
- 普通控件使用约 8px 圆角，主要卡片使用约 12px 圆角。
- 内容区以细边框区分层级；只有弹窗、抽屉、下拉和必要悬浮元素使用明显阴影。
- 动画持续时间控制在 150–220ms，主要用于导航、加载、进度和状态变化。
- 遵循 `prefers-reduced-motion`，为减少动态效果的用户关闭非必要动画。

### 5.3 文案原则

文案从系统管理语言转向行动语言：

- “岗位管理”在用户导航中表达为“岗位机会”或“锁定目标岗位”。
- “暂无数据”必须说明缺少什么，并提供下一步操作。
- AI 结果页先给结论和下一步，再展示明细。
- 管理后台保留准确、简洁的管理术语，不强行套用用户端文案。

## 6. 布局与组件架构

### 6.1 布局层

- `AppLayout.vue`：改造为用户端旅程式应用外壳。
- `AdminLayout.vue`：改造为深色分组侧边栏后台外壳。
- `AnalysisReportPrint.vue`：继续保持独立打印外壳。
- 路由 `meta` 增加旅程领域、导航归属和移动端可见性等纯表现配置；现有 `public` 与 `permission` 语义保持不变。

布局组件不发起新的业务请求，继续消费现有认证与 AI 任务 store。布局中已有的当前用户读取和 AI 任务初始化行为需保持兼容，并在实施时避免重复初始化。

### 6.2 公共组件

优先升级现有组件：

- `PageContainer`：统一最大宽度、页面留白和响应式边距。
- `AppPageHeader`：统一面包屑、标题、说明、主要操作和次要操作。
- `StatCard`：支持指标、趋势、状态和加载占位。
- `StatusTag`：统一状态文本和语义色。
- `AppEmpty`：提供情境说明和下一步操作。

新增组件：

- `JourneyNav`：桌面端求职旅程顶栏。
- `MobileBottomNav`：移动端核心导航。
- `PageHero`：页面级目标、说明和主要操作区域。
- `FilterBar`：统一筛选、查询、重置和折叠行为。
- `TableShell`：统一表格工具栏、边框、空状态、加载和移动降级。
- `AiInsightPanel`：统一 AI 结论、证据、风险与下一步建议的层级。

Element Plus 主题通过全局 CSS 变量和有限公共封装实现。页面不得继续增加无边界的深层选择器和重复临时样式。

## 7. 数据流与兼容性

- 保留 `src/api/` 下所有接口封装及其响应结构。
- 保留 Pinia stores、Axios 拦截器、Token 工具和路由权限守卫。
- 保留 `aiTaskCenter` store 和现有 WebSocket 任务更新机制。
- AI 任务入口从悬浮按钮整合进顶栏，但抽屉和任务状态语义保持不变。
- 保留全部现有 URL，确保书签、刷新、打印页和历史链接可用。
- 页面组件不得为了视觉展示要求后端返回新的字段；派生显示数据在前端计算。
- 不在 UI 迁移中更改删除、禁用、授权等操作的业务语义。

## 8. 加载、空状态与错误处理

- 首次页面加载使用与最终布局一致的骨架屏。
- 局部提交使用按钮或内容区域 loading，避免阻塞整个页面。
- 空状态包含原因、当前上下文和明确下一步操作。
- 接口读取失败优先在对应内容区域展示错误和重试入口。
- 全局消息用于提交成功或失败等操作结果，不用于替代持久页面错误。
- 删除、禁用和权限变更等危险操作继续二次确认。
- WebSocket 中断展示重连状态，并保留现有刷新恢复能力。
- 超长公司名、岗位名、邮箱和 AI 文本必须有换行、截断或展开策略。

## 9. 响应式与可访问性

### 9.1 响应式

重点检查约 375px、768px、1280px 和 1440px 宽度：

- 指标卡、筛选区和报告内容从多列降为单列。
- 用户端顶栏在手机上切换为紧凑顶部栏和底部导航。
- 用户端高频列表优先转换为信息卡。
- 管理后台复杂表格允许横向滚动，并确保关键操作可访问。
- 抽屉、弹窗和固定操作不得被底部导航遮挡。
- 打印报告不继承屏幕导航和移动端固定元素。

### 9.2 可访问性

- 所有交互支持键盘操作并显示清晰焦点状态。
- 图标按钮具有可读名称、`aria-label` 或明确提示。
- 表单标签和错误信息建立可识别关联。
- 正文、按钮和状态文字达到合理对比度。
- 状态同时使用文字、图标或形状，不能只依靠颜色。
- 动画遵循减少动态效果偏好。

## 10. 渐进迁移计划

迁移拆分为六个批次：

1. 设计变量、Element Plus 主题、双布局和公共组件。
2. 登录、注册和工作台。
3. 简历中心和岗位机会。
4. AI 匹配、分析报告、岗位推荐和面试准备。
5. 投递追踪、用户中心、任务中心和反馈。
6. 管理后台、响应式补齐和全站一致性清理。

每个批次必须在前一个批次通过验证后开始。未迁移页面继续使用兼容样式，不采用一次性大规模模板替换。

## 11. 验证与验收

每个批次至少执行：

- `npm run type-check`
- `npm run build`
- 登录、导航、权限、核心 CRUD、AI 任务进度、报告详情和打印页的关键流程检查
- 桌面端与移动端视觉检查
- loading、空状态、错误状态和超长文本检查
- 与改造前截图对比，确认功能入口没有丢失

最终验收标准：

- 现有功能、接口、URL、权限和 WebSocket 零已知回归。
- 新用户能够从工作台理解五阶段求职旅程。
- 用户端核心流程在手机上可以完整操作。
- 管理后台保持高信息密度和桌面操作效率。
- 全站使用统一的颜色、间距、圆角、状态和反馈模式。
- 业务页面不再依赖散落的临时样式修补。

## 12. 版本控制与交付约定

- 所有工作在 `codex/ui-product-redesign` 分支进行。
- 视觉讨论产生的 `.superpowers/` 草案目录加入 `.gitignore`，不进入版本库。
- 设计文档和后续实施计划进入 `docs/superpowers/` 并随分支提交。
- 每个迁移批次使用独立提交，避免无法拆分的巨型提交。
- 未经用户明确要求，不推送远程、不合并 `main`、不部署线上。
