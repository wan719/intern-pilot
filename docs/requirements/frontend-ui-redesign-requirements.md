# InternPilot 前端 UI 重设计｜需求与验收基线 V1.0

> 本文记录重设计范围、业务约束和验收状态。用户已通过简历页原型评审，G2 的本地验证结果见下方矩阵。

## 一、背景、目标和使用者

InternPilot 是面向实习求职者的简历、岗位、AI 匹配、面试和投递管理平台，并包含用户/角色权限、知识库与运营管理后台。本轮动机是使 **C 端用户任务更清晰、内容更易读、错误状态更容易恢复**，同时使 **管理端的信息密度、筛选和操作反馈更适合高频运营**，并保持原有业务能力与安全边界。

| 用户 | 主要目标 | 期望体验 |
| --- | --- | --- |
| C 端求职者 | 管理简历、岗位与投递，查看分析与面试准备 | 清楚下一步操作；简历状态、结果和失败原因直观 |
| 移动端求职者 | 在窄屏完成上述任务 | 关键操作易触达；阅读和交互无明显遮挡、错误和溢出 |
| 管理员 | 用户筛选、角色权限、反馈与知识库管理 | 清楚的管理导航、高效的表格和筛选、明确的危险操作确认 |

**产品体验参考**：C 端借鉴 [Reactive Resume](https://github.com/reactive-resume/reactive-resume) 的内容优先/文档工作区原则；后台借鉴 [Art Design Pro](https://github.com/Daymychen/art-design-pro) 的分组导航与高密度表格。参考是体验方向，不是逐像素复刻、导入参考项目源码或变更技术栈的要求。

**成功判据**：原有核心业务任务仍可完成；关键入口与状态可辨认；桌面/移动/键盘基本可用；管理员权限和确认行为不回归；具体视觉效果通过设计原型与产品评审确认。当前没有独立用户访谈、任务完成时间和转化率基线，不能直接承诺效率提升的百分比。

## 二、范围与非目标

**在范围内**：C 端工作台、简历、岗位/推荐、分析、面试、投递的视觉/交互层次；后台分组导航、表格筛选与操作反馈；全局样式统一、响应式、可访问性和加载/空/失败状态。首个 C 端页面选择 `/resumes`，后台首个页面选择 `/admin/users` 是实施优先级而非产品功能约束。

**不在本轮**：所见即所得简历编辑器、实时 PDF 模板预览或新简历数据模型；后端 API/数据库迁移；改写 AI 任务语义；拆分部署工程；直接生产上线。任何新增功能都应另建需求，并重新评估成本与接口影响。

**继承约束**：保持现有路由和用户可观察的业务能力；不擅自变更 API 请求/响应、文件上传字段、登录会话或 RBAC；前端隐藏操作不替代后端权限；独立报告打印页 `/analysis/reports/:id/print` 不能被全局样式污染；严禁把真实简历、Token 或用户敏感信息放入设计样例与截图。

**事实来源**：实施时优先 `AGENTS.md`、`docs/frontend.md`、`docs/test.md`、源码、接口与实际测试。本文的“保留”是验收约束，实际行为须用当时 SHA 核验。

## 三、产品需求（不绑定组件技术）

| ID | 优先级 | 用户可观察的需求 |
| --- | --- | --- |
| REQ-C01 | P0 | C 端当前任务和主要下一步行动易发现，并保留既有导航入口 |
| REQ-C02 | P0 | 简历列表、详情、解析状态、默认状态、版本入口可用且信息清晰 |
| REQ-C03 | P0 | 上传、设为默认、删除等操作具备真实的处理中/成功/失败/确认反馈，失败可恢复 |
| REQ-C04 | P1 | 简历版本、岗位/推荐、面试与投递等原有业务流不因视觉改造改变含义 |
| REQ-C05 | P0 | AI 长任务、结果、刷新恢复和失败重试语义不被界面改动破坏 |
| REQ-A01 | P0 | 后台导航、列表筛选、分页和管理入口符合原有权限规则 |
| REQ-A02 | P0 | 后台角色分配、启用/禁用与详情操作正确，危险动作需确认 |
| REQ-X01 | P0 | 登录/注册、403、个人中心、报告打印等跨页面功能不受全局样式影响 |
| REQ-N01 | P0 | 桌面和手机都能完成关键任务，不能出现阻碍操作的溢出/遮挡 |
| REQ-N02 | P0 | 重要交互支持键盘、可见焦点、明确标签与合理弹窗焦点管理；目标参考 WCAG 2.2 AA，不能宣称已达标 |
| REQ-N03 | P0 | 加载、空数据、错误、权限受限、处理中等状态清晰且不只靠颜色表达 |
| REQ-N04 | P0 | 前后端 API、权限、响应式导航、打印、现有测试和构建行为保持兼容 |
| REQ-N05 | P1 | 不引入未经解释的明显页面/构建性能退化；待真实基线再制定量化阈值 |

P0 为每批交付适用的硬要求；P1 可在相应后续阶段验证，不允许通过降级优先级绕过安全和数据边界。

## 五、变更管理与待确认问题

- **视觉评审**：仅以参考项目截图评判“相似”不够，需能说明页面的信息层次、操作可达性与失败恢复。用户已通过简历页原型评审。
- **新增能力**：从上传解析扩展到实时编辑/PDF 预览涉及新的编辑模型、保存、导出与兼容设计，明确排除出本轮；如用户决定新增，独立开 Feature。
- **信息架构**：首批不改原有求职旅程路由的语义；以后若调整导航名称/分组，要列出新旧映射并更新验收。
- **测试成本**：已有简历页桌面与移动截图及跨页样式对照。性能数据待按后续页面范围采集。
- **授权**：本文件是需求初稿，用户对 UI 原型的接受不自动授予生产访问、合并或发布授权。
